# Android Farm — چند گوشی اندروید مجازی روی یک سرور

هر دستگاه یک اندروید کامل است (Redroid داخل Docker) با **Google Play** و اجرای اپ‌های ARM، و هویت جدا:
مدل/برند، سریال، MAC، IMEI (فرمت معتبر Luhn)، Android ID و داده‌ی کاملاً جدا.
صفحه‌ی هر گوشی از مرورگر (کامپیوتر یا خود موبایل) با لمس کامل کنترل می‌شود،
و ساخت پروفایل، ساخت گوشی، روشن/خاموش، پروکسی و بکاپ همه از یک **پنل وب** انجام می‌شود.

## نصب (یک خط)

```bash
curl -fsSL https://raw.githubusercontent.com/AssA7778/Android-emulator/main/bootstrap.sh | sudo bash
```

- با دامنه (HTTPS واقعی): `... | sudo bash -s -- --domain droid.example.com` (رکورد A دامنه باید به IP سرور اشاره کند)
- فقط بررسی سرور، بدون نصب: `... | sudo bash -s -- --check`
- بدون پنل وب: `... | sudo bash -s -- --no-web`
- بدون Google Play (اندروید ۱۳ خام): `... | sudo bash -s -- --no-gapps`

در پایان، آدرس پنل وب و رمز در `/etc/android-farm/web-credentials` ذخیره می‌شود.

## پنل وب

| آدرس | چه چیزی |
|---|---|
| `https://<IP>:8443` (یا `https://<دامنه>`) | **پنل مدیریت**: گوشی‌ها، پروفایل‌ها، بکاپ‌ها |
| `https://<IP>:8444` (یا `https://<دامنه>:8444`) | صفحه‌ی گوشی‌ها (ws-scrcpy) |

هر دو با همان `admin` و رمز باز می‌شوند. در پنل:

- **گوشی‌ها:** کارت هر گوشی با وضعیت، مدل، IMEI و پروکسی؛ دکمه‌های «باز کردن صفحه» (صفحه‌ی همان گوشی مستقیم باز می‌شود)، روشن/خاموش، پروکسی، مشخصات، GSF، بکاپ و حذف. فرم «ساخت گوشی تازه» اجازه می‌دهد هویت را از پروفایل‌های آزاد انتخاب کنی یا هویت تصادفی با مدل دلخواه بگیری.
- **پروفایل‌ها:** ساخت یکی یا چندتا یکجا، دیدن هویت‌ها و اینکه هرکدام به کدام گوشی داده شده، و دکمه‌ی «ساخت گوشی» کنار هر پروفایل آزاد.
- **بکاپ‌ها:** دانلود، آپلود و بازگردانی (پایین‌تر).
- **کارها:** کارهای طولانی (مثل بوت) در پس‌زمینه اجرا می‌شوند و خروجی‌شان همین‌جا زنده دیده می‌شود.

پنل خودش فقط روی `127.0.0.1:8100` است و همه‌ی کارها را با همان دستور `droid` انجام می‌دهد، پس قانون‌ها در پنل و خط فرمان یکی است.

## بکاپ و بازگردانی

یک بکاپ = **هویت کامل** (مدل، IMEI، MAC، سریال، پروفایل) + **همه‌ی داده‌ها و حافظه‌ی گوشی** (اپ‌های نصب‌شده، اکانت‌ها، فایل‌ها، تنظیمات) در یک فایل `tar.gz`.

```bash
droid backup acc1                         # در /var/lib/android-farm/.backups/
droid backup acc1 -o /root/acc1.tar.gz
droid restore acc1-20260923-101500.tar.gz               # با همان نام
droid restore acc1-20260923-101500.tar.gz --name acc7   # با نام تازه
```

- اگر گوشی روشن باشد، برای بکاپ سالم چند ثانیه خاموش و بعد دوباره روشن می‌شود (کپی دیتابیس‌های اندروید در حال کار خراب درمی‌آید).
- بازگردانی روی **سرور دیگر** هم کار می‌کند: فایل را در پنل آپلود کن و «بازگردانی» بزن. پورت adb تازه گرفته می‌شود و پروفایل ذخیره‌شده هم اگر آنجا نباشد برمی‌گردد.
- دو گوشی با یک هویت ساخته نمی‌شود: اگر گوشی اصلی هنوز روی همین سرور هست، بازگردانی رد می‌شود.
- فایل بکاپ یعنی دسترسی کامل به اکانت‌های آن گوشی؛ جای امن نگهش دار.

## مشخصات سرور

| تعداد گوشی | CPU | RAM | دیسک |
|---|---|---|---|
| ۱–۲ | ۲ هسته | ۴ گیگ | ۳۰ گیگ |
| ۳–۵ (پیشنهادی) | ۴ هسته | ۸ گیگ | ۶۰ گیگ SSD |
| هر گوشی اضافه | +۱ هسته | +۱.۵ گیگ | +۸ گیگ |

- **Ubuntu 22.04 / 24.04، x86_64.**
- **KVM لازم نیست.** Redroid مجازی‌سازی نمی‌کند؛ اندروید مستقیم روی کرنل لینوکس اجرا می‌شود و فقط ماژول `binder_linux` لازم است که کرنل‌های معمولی Ubuntu دارند.
- فقط VPSهای **OpenVZ / LXC** جواب نمی‌دهند، چون اجازه‌ی لود ماژول کرنل نمی‌دهند. هنگام خرید، نوع مجازی‌سازی را «KVM» انتخاب کن. `--check` این را قبل از نصب می‌گوید.

## Google Play و اپ‌ها

- پیش‌فرض نصب، اندروید ۱۲ با **Google Play** (MindTheGapps) و **libndk** است تا اپ‌هایی که فقط نسخه‌ی ARM دارند (بیشتر اپ‌های فروشگاه) روی سرور x86 اجرا شوند. نسخه‌ی ۱۲ انتخاب شده چون libndk روی ۱۳ کار نمی‌کند.
- ایمیج هنگام نصب با [redroid-script](https://github.com/ayasa520/redroid-script) (نسخه‌ی قفل‌شده و تست‌شده) ساخته می‌شود؛ ۳ تا ۱۰ دقیقه و حدود ۴ گیگ فضا.
- Play Store را باز کن و با اکانت گوگل وارد شو. اگر گفت «دستگاه تأییدنشده» (Device is not Play Protect certified):
  ```bash
  droid gsf acc1     # شناسه‌ی GSF را می‌دهد
  ```
  این عدد را با همان اکانت گوگل در https://www.google.com/android/uncertified ثبت کن، چند دقیقه صبر کن و گوشی را یک بار خاموش/روشن کن (`droid stop acc1 && droid start acc1`). این صفحه‌ی رسمی خود گوگل برای دستگاه‌های ثبت‌نشده است.

## پروفایل‌های هویت

هر بار که پروفایل می‌سازی، مدل، سریال، MAC و IMEI تازه و تصادفی می‌گیرد و ذخیره می‌شود. بعد هر وقت خواستی، از روی آن گوشی می‌سازی:

```bash
droid profile new                       # یک پروفایل تصادفی (نام خودکار p1، p2، …)
droid profile new --count 5             # ۵ پروفایل یکجا
droid profile new work --model "Pixel 8"
droid profile list                      # همه‌ی پروفایل‌ها + گوشی‌ای که از هرکدام ساخته شده
droid profile show work
droid profile rm p3
droid new acc1 --profile work           # گوشی با همان هویت ذخیره‌شده
```

- هر پروفایل فقط به یک گوشی داده می‌شود؛ اگر دو گوشی یک هویت داشته باشند دیگر هویت جدا نیستند.
- پروفایلی که گوشی رویش ساخته شده پاک نمی‌شود، مگر اول گوشی را با `droid rm <name> --purge` پاک کنی.
- پروفایل‌ها در `/var/lib/android-farm/.identities/` با دسترسی `600` هستند.

## استفاده

```bash
droid new acc1                                   # گوشی با مدل و هویت تصادفی
droid new acc2 --model "Pixel 7"                 # مدل مشخص (لیست: droid models)
droid new acc3 --proxy 1.2.3.4:8080 --mem 3g --cpus 2
droid list                                       # همه‌ی گوشی‌ها + IMEI
droid info acc1                                  # هویت کامل + مقادیر زنده‌ی داخل گوشی
droid view acc1                                  # آدرس دیدن صفحه
droid proxy acc1 5.6.7.8:3128 | off              # عوض کردن پروکسی
droid stop acc1 / droid start acc1
droid shell acc1                                 # ترمینال داخل گوشی
droid rm acc1                                    # حذف کانتینر، داده می‌ماند
droid rm acc1 --purge                            # حذف کامل همراه اکانت‌ها
droid gsf acc1                                   # شناسه‌ی ثبت در گوگل
```

نصب APK: `adb -s 127.0.0.1:6000 install app.apk` (پورت هر گوشی در `droid list` آمده است).

## کار با لمس

- در پنل وب روی کارت گوشی **«باز کردن صفحه»** را بزن (یا در `:8444` روی **H264 Converter** همان گوشی).
- لمس، کشیدن، اسکرول و مولتی‌تاچ (Ctrl+کلیک روی کامپیوتر) کار می‌کنند. روی موبایل هم مستقیم با انگشت کار می‌کند.
- دکمه‌های Back / Home / Recents در نوار کنار صفحه هستند. کیبورد کامپیوتر مستقیم داخل گوشی تایپ می‌کند.
- صفحه‌ی گوشی هیچ‌وقت خاموش یا قفل نمی‌شود، انیمیشن‌ها کوتاه‌تر شده‌اند و چرخش خودکار خاموش است تا تصویر به‌هم نریزد.
- وضوح ۷۲۰ پیکسل انتخاب شده تا روی رندر نرم‌افزاری روان بماند.
- روان‌ترین حالت روی کامپیوتر: [scrcpy](https://github.com/Genymobile/scrcpy) از راه تونل SSH (دستورش را `droid view` می‌دهد).

## نکته‌های مهم درباره‌ی هویت

- **مدل:** مدل و برند با یک فایل `build.prop` جدا برای هر گوشی ست می‌شوند (نه آرگومان بوت)، چون init در Redroid آرگومان‌ها را روی فاصله می‌شکند و «Pixel 7» می‌شد «Pixel».
- **IMEI:** برای هر گوشی یک عدد ۱۵ رقمی با رقم کنترل Luhn ساخته می‌شود که کاملاً تصادفی است و از هیچ دستگاه واقعی کپی نمی‌شود. در `droid list` و `droid info` نمایش داده و به‌صورت prop داخل سیستم ست می‌شود. ولی از **اندروید ۱۰ به بعد، اپ‌های معمولی (تلگرام، واتس‌اپ، اینستاگرام و …) اصلاً اجازه‌ی خواندن IMEI را ندارند** و Redroid هم مودم/سیم‌کارت ندارد.
- چیزی که واقعاً گوشی‌ها را از هم جدا می‌کند **Android ID، داده‌ی جدا، مدل و مهم‌تر از همه IP** است. برای چند اکانت، به هر گوشی یک پروکسی جدا بده.
- پروکسی از نوع HTTP سیستمی است. بیشتر اپ‌ها از آن استفاده می‌کنند، ولی بعضی اپ‌ها (مثلاً تلگرام) پروکسی داخلی خودشان را دارند و بهتر است همان‌جا هم تنظیم شود.
- ابزار مخفی‌سازی روت یا جعل Play Integrity در این پروژه **نیست**. بعضی سرویس‌ها استفاده از شبیه‌ساز یا چند اکانت را خلاف قوانینشان می‌دانند و مسئولیتش با خود کاربر است.

## امنیت

- پورت adb هر گوشی فقط روی `127.0.0.1` باز است، چون adb یعنی دسترسی کامل به گوشی.
- پنل و صفحه‌ی گوشی‌ها فقط از راه Caddy با رمز و HTTPS در دسترس‌اند. پورت‌های داخلی ۸۰۰۰ و ۸۱۰۰ از بیرون بسته‌اند.
- کارهای پنل فقط با هدر مخصوص خود پنل پذیرفته می‌شوند تا سایت دیگری نتواند با رمز ذخیره‌شده‌ی مرورگر کاری انجام دهد (CSRF).
- پروفایل‌ها با دسترسی `600` در `/var/lib/android-farm` ذخیره می‌شوند.

## بدون binder (حالت اضطراری)

اگر `--check` گفت کرنل binder ندارد و راهی برای عوض کردن VPS نیست، تنها راه باقی‌مانده Android Emulator رسمی (AVD) با شتاب نرم‌افزاری است:
`emulator -avd x -accel off -no-window -gpu swiftshader_indirect`.
این روش کار می‌کند ولی **۵ تا ۱۰ برابر کندتر** است و برای استفاده‌ی روزمره پیشنهاد نمی‌شود. راه درست یک VPS از نوع KVM است.
